# JavaSamples

Навчальний проєкт на Spring Boot: тут крок за кроком реалізується архітектура застосунку
і додаються нові фічі для вивчення того, як Spring працює під капотом (DI, автоконфігурація,
життєвий цикл бінів, обробка запитів тощо).

## Стек

- Java 21
- Spring Boot 3.3 (web, validation, actuator, devtools)
- Maven
- JUnit 5 + MockMvc для тестів

## Архітектура

Класичний шаруватий поділ, кожен шар — окремий пакет:

```
com.javasamples
├── web          — REST-контролери (шар представлення)
├── service      — бізнес-логіка
├── repository   — доступ до даних (зараз in-memory, легко замінити на JPA)
├── domain       — доменні моделі
├── dto          — об'єкти запиту/відповіді
├── exception    — власні винятки та @RestControllerAdvice
└── config       — конфігурація бінів (@Configuration)
```

Приклад наскрізного потоку реалізовано на фічі `Task`
(`TaskController` → `TaskService` → `TaskRepository`), щоб було видно повний шлях запиту.

## Запуск в IntelliJ IDEA

1. `Open` → вказати корінь репозиторію (де лежить `pom.xml`). IDEA сама розпізнає Maven-проєкт.
2. Дочекатись завантаження залежностей (перший раз піде через мережу).
3. Відкрити `src/main/java/com/javasamples/JavaSamplesApplication.java`
   і натиснути зелений ▶ біля класу (Run) — застосунок підніметься на `http://localhost:8080`.
4. Перевірити: `GET http://localhost:8080/actuator/health` має повернути `{"status":"UP"}`.

Запуск з консолі:

```bash
./mvnw spring-boot:run
```

Тести:

```bash
./mvnw test
```

## API (приклад)

| Метод | Шлях                     | Опис                     |
|-------|---------------------------|--------------------------|
| GET   | `/api/tasks`               | список задач             |
| GET   | `/api/tasks/{id}`           | одна задача               |
| POST  | `/api/tasks`                | створити задачу           |
| POST  | `/api/tasks/{id}/complete`  | позначити виконаною       |
| DELETE| `/api/tasks/{id}`           | видалити задачу           |

## Плани

Проєкт буде поступово наповнюватись новими темами: JPA/Hibernate, Spring Security,
кешування, асинхронність, events, AOP, Testcontainers тощо — кожна як окрема фіча
поверх наявної архітектури.
